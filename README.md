# BackupFolderManager

Windows 用のバックアップ管理アプリです。.NET 10 Desktop Runtime、7-Zip、MultiPar が必要です。

## プロジェクト構成

- `src/BackupFolderManager`: WPF アプリ本体。
- `src/BackupFolderManager.Core`: バックアップ、復元補助、外部プログラム実行、設定保存を扱う C# ライブラリ。
- `tests/RestoreFiles.Checks`: 独立した検証用コンソールプロジェクト。共有ライブラリを参照し、アプリ本体には含めません。

`src/BackupFolderManager.slnx` に全プロジェクトを登録しています。

## 必要なプログラム

バックアップの開始前に `7z.exe` と `par2j64.exe` の存在を確認します。展開には `7z.exe` のみ必要です。
不足している場合は処理を開始せず、プログラム名と確認した場所をログに表示します。起動直前にも存在を再確認し、終了コードが 0 以外なら失敗として扱います。

検出する場所は次のとおりです。

- アプリの exe と同じフォルダ。
- Program Files または Program Files (x86) 配下の `7-Zip/7z.exe`、`MultiPar/par2j64.exe`。
- `par2j64.exe` はバックアップ対象の親フォルダに置くこともできます。

## 使い方

1. `dotnet run --project src/BackupFolderManager` で起動します。
2. 「フォルダ選択・追加」で、バックアップするフォルダが入った親フォルダを複数選びます。未接続のパスは入力欄に絶対パスを入力して「パスを追加」で登録できます。
3. 「圧縮対象の階層」で「直下のフォルダ」または「孫フォルダ」を選んで登録します。既存の登録を変更する場合は、上の登録一覧で行を選び「選択した登録に適用」を押します。「選択フォルダをアーカイブ」で、各登録の対象階層にあるデータ入りのフォルダをまとめて `.7z` に圧縮します。同名アーカイブがあるフォルダはスキップし、既存の出力は上書きしません。
4. **初期状態では検証成功後に元フォルダの中身を削除し、空フォルダを残します。** 実行時にも確認が表示されます。保持したい場合は「検証後に元フォルダの中身を削除する」を外してください。
5. 下の一覧で個別のフォルダを選び、「選択フォルダを展開／圧縮」でそのフォルダだけを処理します。アーカイブだけがある行は展開し、データだけがある行は圧縮します。両方がある場合は操作ダイアログで「展開・同一性チェック」「再圧縮（.7z を置換）」「何もしない」を選べます。展開後はエクスプローラーでフォルダを開きます。

展開後にファイルを更新した場合は「再圧縮（.7z を置換）」を選びます。操作ダイアログに、サブフォルダを含む展開ファイルの最新更新日時と、既存 `.7z` の更新日時を表示します。日時は目安であり、削除・改名・日時を維持した変更は判定できません。日時にかかわらず再圧縮できます。日時の走査はこのダイアログを開く際にバックグラウンドで行い、通常の一覧更新では行いません。

再圧縮は現在の展開内容から新規作成するため、削除したファイルが旧アーカイブから引き継がれることはありません。新しいアーカイブ・SHA256・PAR2 を一時フォルダで作成し、全検証に成功してから既存の同名 `.7z`・SHA256・PAR2（分割回復ファイルを含む）を置き換えます。既存の `.zip` は保持します。上の一括アーカイブボタンは引き続き既存アーカイブのあるフォルダをスキップします。

上の登録一覧と下のフォルダ一覧は、それぞれ Ctrl / Shift キーで複数選択できます。上のボタンは上の選択、下のボタンは下の選択だけを対象にします。下の一覧で空フォルダを選んだ場合はスキップします。

対象階層は登録ごとに `settings.json` に保存します。以前のパスだけの設定は「直下のフォルダ」として読み込みます。
「孫フォルダ」の場合、例えば登録が `D:\parent` なら、`D:\parent\childA\grandchildA` を `D:\parent\childA\grandchildA.7z` に圧縮します。`childB` 内の孫フォルダは `childB` 内に保存します。SHA256・PAR2 も同じ保存先です。中間の `childA`・`childB` 自体や、その直下の単独ファイルは圧縮・削除しません。各孫フォルダ内のさらに深いデータは、その孫フォルダのアーカイブに含めます。
孫フォルダ設定でも、アーカイブ済み・展開・再圧縮の操作は同じです。中間フォルダのリンク・ジャンクションはたどらず、アクセスできない中間フォルダとともにログに記録してスキップします。

下の一覧はアーカイブ単位ではなく、各登録の対象階層にあるフォルダ単位で表示します。「親フォルダ」列にはアーカイブの実際の保存先を表示します。

| 状態 | 判定 |
|---|---|
| 展開済み | フォルダ内にデータがあり、同名アーカイブなし |
| アーカイブ済み | フォルダは空で、同名アーカイブあり |
| アーカイブ済み（フォルダなし） | 同名アーカイブだけが存在する |
| 展開済み・アーカイブあり（未照合） | データとアーカイブの両方が存在する |
| 空フォルダ | データも同名アーカイブもない |

状態表示は存在確認によるもので、アーカイブの正常性やデータの一致を保証するものではありません。一覧表示ではファイル内容の読み込みやハッシュ計算を行いません。
元フォルダが存在しなくても同名アーカイブがあれば一行として表示します。同じ名前の `.7z` と `.zip` は一つのフォルダ行にまとめ、展開時に使うアーカイブを選べます。

登録パスは **exe と同じフォルダの `settings.json`** に保存し、次回起動時に復元します。相対的な実行場所ではなく、exe の配置先を使います。
新しい保存先に設定がなく、旧 `%LOCALAPPDATA%\BackupFolderManager\folders.json` があれば初回読込時に移行します。旧ファイルは削除しません。
保存先に書き込み権限がない場合は、保存先と理由を画面に表示します。

未接続・存在しないパスも登録に残します。一覧に状態を表示し、バックアップ時はスキップしてログに記録します。
再接続後は「一覧更新」で再検出できます。一つのパスや子フォルダでバックアップに失敗しても他の処理を続行します。
「登録解除」は一覧の登録だけを削除し、ディスク上のデータは削除しません。

## バックアップ工程

公開メソッド `BackupService.BackupAsync` 内で、private メソッドを次の順序で呼び出します。

1. 外部プログラム・既存出力・元データの確認。
2. 圧縮とアーカイブテスト。
3. 一時展開して、元データとの相対パス・空フォルダ・サイズ・SHA256 を照合。
4. 元データが処理中に変わっていないか再確認。
5. アーカイブの SHA256 ファイルを作成。
6. PAR2 の作成と検証。
7. アーカイブの SHA256 と元データをもう一度確認。
8. 再圧縮の場合、新しい出力一式に置き換え。
9. 削除指定時のみ元フォルダの中身を削除。

削除工程に到達するまでに失敗した場合、元データは削除しません。削除自体の途中でエラーになった場合は一部削除済みの可能性があるためログで区別します。
通常の新規圧縮で失敗した場合、作成済みのアーカイブ・SHA256・PAR2 は調査用に残します。再実行時も上書きしません。
再圧縮の検証中に失敗した場合は旧出力を変更せず、一時出力を削除します。置換中のエラーでは旧出力の復元を試みます。復元できなかった旧ファイルは `.backup_verify_previous_<ランダムID>` に残し、ログに場所を表示します。複数ファイルの置換は一括の原子的操作ではないため、置換中にプロセスが終了した場合にもこの退避先を確認してください。

## 展開

フォルダ一覧には登録した全親フォルダの対象階層を表示します。展開前に隣接する `.sha256` があれば照合します。
`D:\Games\Game.7z` の復元先は `D:\Games\Game` です。アーカイブ内のルートが同名フォルダ一つの場合は、その中身を復元し、`Game\Game` の二重構造を避けます。フラットな ZIP も同名フォルダへ展開します。

復元先が空、または存在しない場合はそのまま復元します。既存データがある場合は次のいずれかを選びます。

- **上書きする**: 同名ファイルを置き換えます。復元先にしかないファイルやフォルダは残します。ファイルとフォルダの種類が競合する場合はエラーにします。
- **同一性チェック**: 一時展開した内容と復元先の相対パス、空フォルダ、全ファイルのサイズ・SHA256 を比較します。既存データは変更せず、一致時は復元先を開きます。
- **何もしない**: 展開もチェックも行いません。ダイアログを閉じた場合も同様です。

一時展開先 `.backup_verify_restore_<ランダムID>` は処理後に削除します。削除できない場合はログにパスを残します。
リンク・ジャンクションを含むバックアップ対象・復元先・展開内容は処理しません。
処理中はアプリを閉じられません。進行状況や失敗理由は画面下部のログで確認できます。

## 検証

```powershell
dotnet build src/BackupFolderManager.slnx
dotnet run --project tests/RestoreFiles.Checks
```

検証プロジェクトの `Program.cs` が検証全体を起動し、`BackupChecks.cs` が設定保存、工程順序、各工程の失敗時の元データ保持、元データやアーカイブの変更検出を確認します。
一時データだけを使います。7-Zip があれば実際の圧縮・復元も確認します。バックアップ工程の検証では PAR2 実行を代替し、MultiPar の実機検証とは区別しています。
